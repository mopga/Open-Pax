## 1. Как устроен сценарий (пресет) в PaxHistoria

**Главный вывод: при старте игры страны не генерируются.** Пресет — это готовые данные плюс набор промптов. Модель вызывается только в ходе игры. Наш BalanceAgent, который делает по одному вызову на страну, архитектурно лишний.

Пресет хранится как два документа (так написано в окне «Размер документа»):

- **Документ промптов** — промпты, правила симуляции, начальная хронология, базовые слои карты, настройки.
- **Документ данных** — элементы карты, описания стран, события, действия игроков, катализаторы, чаты.

### Разделы страницы пресета (она же редактор)

| Раздел | Что внутри | Видит ли ИИ |
|---|---|---|
| Шапка | Обложка, название, автор; счётчики игр, раундов, копий и избранного. Кнопки «Опубликовать», «Копировать», «Версии» (`?versionID=N`), «Соавторы», «Играть сейчас». Автосохранение («Сохранено») | нет |
| Об этом сценарии | Описание, плашки «Начинается 1 января 1960 н. э.» и «Исторический • Холодная война» | нет |
| Начальная временная линия | «Мир до раунда 1» — лор и события до старта | да → `${WORLD_BEFORE_ROUND_ONE_TEXT}` |
| Правила симуляции | Свободный текст с правилами для ИИ | да → `${HISTORICAL_PRESET_SIMULATION_RULES}` |
| Карта регионов | Встроенный редактор карты (ниже) | через описание карты |
| Вступительные слайды | До 10 слайдов для игрока при первом входе | нет |
| Государства | Карточки: флаг, имя, «N регионов»; поиск, сортировка, «Создать новое государство» | да |
| Рекомендуемые государства | Подсказки, за кого начать | нет |
| Начальные чаты | Чаты, которые добавляются в каждую новую игру | да |
| Элементы карты | Города, столицы, батальоны: владелец, форма значка, «Динамический» (движется с регионом) или «Статичный» | да |
| Подсказки ИИ | 12 настраиваемых промптов | — |
| Расширенные настройки | Консолидация (старт с раунда 7, блок 7), параметры отображения карты, размер документа | — |

### 12 промптов

«Чат с пользователем», «Чат с советником», «Скачок вперёд» (3 этапа), «Автоматический скачок вперёд» (3 этапа), «Действия», «Следующий говорящий», «Описание в действие», «Объединитель событий», «Создание катализатора», «Исполнитель катализатора», «Обобщитель катализатора», «Мастер игры».

Как устроен каждый промпт:

- Промпт — это **JS-функция, которая возвращает template literal**: `` return `...${PLAYER_POLITY}...` ``. В ней можно писать выражения, например `${isBeta ? A : B}`.
- Переменные — это **именованные функции-хелперы** с описанием (`PLAYER_POLITY`, `GRAND_MAP_DESCRIPTION`, `ALL_EVENTS_WITH_CONSOLIDATION`, `PLAYER_POLITY_REGIONS`, `DIFFICULTY_DESCRIPTION_CHATS`, `PREVIOUS_STAGE_OUTPUT` и др.; полный список — в расшифровках).
- Хелперы бывают пользовательские: например, `RUSSIA_FIRST_LAYER_BORDERING_REGIONS` — регионы-соседи первого, второго и третьего слоя. Их можно создать, купить в «Магазине» или импортировать. Неиспользуемые хелперы удаляются одной кнопкой.
- У каждого промпта конвейер из четырёх шагов: «Шаблон → Структура вывода → Модель ИИ → Очистка». То есть схема ответа, **своя модель для каждого промпта** и постобработка.
- Вкладки окна промпта: «Источник промпта», «Редактировать», «Тестировать», «Оценить».
- Язык вывода задаётся переменной `${language}`: инструкции на английском, а ответ на языке игрока.

### Новые для нас механики

- **Катализаторы** — интерактивная сцена (битва, речь, переговоры) длительностью до 2–3 игровых дней с выбором вариантов и шкалой прогресса до 100%. Когда сцена завершается, её краткое изложение попадает в историю. Работают три промпта: создание, исполнение, обобщение.
- **Мастер игры** — «чит»-ассистент. По просьбе игрока он передаёт регионы, создаёт, меняет и распускает государства, меняет флаги и элементы карты.
- **Многоэтапный скачок** — 3 этапа, следующий получает вывод предыдущего через `PREVIOUS_STAGE_OUTPUT`.

## 2. Что это значит для архитектуры Open-Pax

| Сейчас у нас | Как у PaxHistoria | Что сделать |
|---|---|---|
| BalanceAgent: 41–112 вызовов модели при старте | Пресет уже содержит регионы, владельцев, элементы и описания | Старт без вызовов модели, мир берётся из данных пресета |
| `preset.json`, `lore.md`, `rules.md`, частичные переопределения промптов | Документ промптов и документ данных | Формат пресета v2: те же два «документа», версии |
| Промпты захардкожены в `prompts/*.ts`, у переменных `${VAR}` фиксированный набор | 12 слотов промптов, каждый — шаблон и хелперы; своя модель для каждого слота | Реестр хелперов (наши `prompt-builder` переменные уже почти совпадают по именам) и редактируемые шаблоны в пресете |
| Регион = страна | Регион мельче страны (провинции, города, моря); государство владеет многими регионами | Модель «регион ≠ государство», см. карту |
| Чаты отключены | Чаты и начальные чаты — часть пресета | Решить отдельно |

Предлагаемый порядок: формат пресета v2 → регионы admin-1 → старт без LLM → редактируемые промпты → катализаторы и мастер игры.

## 3. Карта: в чём разница

Что видно у PaxHistoria (`docs/ref/pax-editor`, кадры редактора и первое видео):

| Свойство | PaxHistoria | Open-Pax сейчас |
|---|---|---|
| Покрытие | Вся суша поделена на регионы; ничья земля показывает природный рельеф | Только страны пресета, остальное пусто |
| Детализация | Регионы уровня областей, штатов и провинций (у Китая 37, у Канады 10), города, моря и проливы тоже регионы | Одна страна = один полигон |
| Подложка | Рельеф и текстура суши просвечивают сквозь цвет владельца; океан тёмно-синий (≈`#0b0b35`) со слабыми границами морских зон | Сплошной `#0d1117` и сетка |
| Границы | Тонкие тёмные между регионами (проявляются при зуме — «Диапазон затухания границ»), толще между государствами | Одна толщина для всех |
| Подписи | Одна на государство (на крупных отдельных кусках — своя, как PORTUGAL в Анголе и Мозамбике). Serif-шрифт, капс, большой межбуквенный интервал, кремовые с тёмным контуром, **изогнуты вдоль оси страны**, размер зависит от площади, «Удлинение линий меток» 0.015 | DOM-маркеры, sans-serif, горизонтальные, одного размера, наезжают друг на друга |
| Элементы карты | Города, столицы (звезда), батальоны. Размер задан «в метрах на местности» (по умолчанию 10 км), есть диапазон зума появления, шрифт настраивается | Эмодзи-маркеры со случайными координатами |
| Управление | Поиск, слои, настройки, зум; подсказка «Регион \| Владелец» | Зум |
| Проекция | Меркатор, мир повторяется по горизонтали | Меркатор, без явного повтора |

## 4. Технический план карты

Стек остаётся прежним (MapLibre GL). Всё работает офлайн, данные — public domain (Natural Earth, NASA), шрифты под OFL.

### M1 — «весь мир и правильная отрисовка» (2–3 дня, без смены модели данных)
- Все 243 страны Natural Earth получают владельца: по умолчанию сами себя, пресет переопределяет. Ничейной земли нет.
- Геометрия загружается в источник один раз. Цвет владельца задаётся через `feature-state` (`promoteId`), и при переходе региона геометрия не перезагружается.
- Подложка рельефа: растр Natural Earth Shaded Relief (`SR_LR`, 1:50m) нарезается скриптом на XYZ-тайлы z0–6 (`sharp`) и кладётся в `frontend/public/tiles/relief`. Слой стоит **над** заливками с `raster-opacity` ≈ 0.35, так рельеф «тонирует» цвет владельца. Океан — тёмно-синий фон, опционально батиметрия (`OB_LR`).
- Шрифт: PT Serif или Cormorant (кириллица, OFL) переводится в PBF-глифы (`@maplibre/font-maker`) в `frontend/public/glyphs`. Подписи становятся `symbol`-слоем вместо DOM-маркеров: капс, `text-letter-spacing` 0.25, halo, коллизии считает MapLibre.
- Границы между государствами — отдельный слой. Заранее посчитанные общие рёбра регионов фильтруются по признаку «у соседей разные владельцы».
- `renderWorldCopies`, подсказка «Регион | Владелец», поиск по государствам и регионам с перелётом камеры.

### M2 — изогнутые подписи (2 дня)
- Для каждого государства (и каждого куска больше порога площади) строится «линия подписи»:
  - главная ось многоугольника (PCA вершин);
  - вдоль оси N станций; в каждой — перпендикулярная хорда, внутри полигона берётся её середина;
  - ломаная из середин сглаживается (Chaikin) и удлиняется на 1.5%, как их параметр 0.015.
- `symbol-placement: line-center`, `text-max-angle` ≈ 25°. Размер шрифта — свойство фичи из длины линии и длины названия, растёт с зумом экспоненциально.
- Пересчёт в Web Worker только для государств, чьи владения изменились.

### M3 — регионы мельче стран (4–6 дней, вместе с пресетом v2)
- Скрипт сборки (`mapshaper` из npm): Natural Earth admin-1 (≈4.6k областей) → упрощение и слияние мелких по полю `region` → ≈1.5–3k регионов. Плюс морские регионы из `geography_marine_polys`. На выходе `regions.geojson` с полями `id`, `name`, `nameRu`, `iso3`, `type: land|sea`.
- Граф соседства и общие рёбра считаются при сборке (у нас уже есть `utils/borders.ts`) и пригодятся валидатору фронтов.
- Пресет хранит `owner` для каждого региона, у государств есть имя, цвет, флаг и описание. Карта подаётся моделям как список «государство → регионы» (их `GRAND_MAP_DESCRIPTION`).
- Если GeoJSON окажется тяжёлым — векторные тайлы (`geojson-vt` в воркере или PMTiles при сборке).

### M4 — элементы карты (2–3 дня)
- Города из Natural Earth populated places с фильтром по рангу, столицы звездой, батальоны.
- Размер в «метрах на местности» через экспоненциальную функцию от зума и диапазон зума появления, как в их «Параметрах отображения карты».
- Границы регионов проявляются с зумом (`line-opacity` по зуму).

### M5 — редактор карты для пресетов (позже)
- Инструменты по образцу PaxHistoria: выбор, мульти, кисть владения, рисование и вырезание, правка вершин, заливка дыр, статичные и мобильные элементы, туман, отмена, проверка топологии.
- Сначала нужны «Кисть» и «Выбор»: их достаточно, чтобы собирать исторические пресеты (Холодная война с СССР и ГДР и т.п.).

### Объём данных
- Тайлы рельефа z0–6: ≈30–60 МБ — генерируются скриптом, в git не кладутся.
- Глифы: ≈1–2 МБ.
- Регионы admin-1 после упрощения: ≈5–10 МБ GeoJSON (или меньше в тайлах).

## 5. С чего начать

M1 даёт самый заметный визуальный скачок и не ломает текущую модель данных. После него — M2 (изогнутые подписи). M3 лучше делать вместе с форматом пресета v2: оба меняют модель «регион / государство».
