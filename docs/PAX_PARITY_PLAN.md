# Open-Pax: план функционального паритета с Pax Historia

Дата аудита: 2026-08-02

## Цель

Сделать локальный, self-hosted симулятор с тем же главным ощущением игры:

1. Игрок ставит мир на паузу и задаёт несколько приказов.
2. Может советоваться с советником; дипломатические чаты сознательно не входят в продукт.
3. Выбирает дату следующего раунда или «следующее важное событие».
4. Один симуляционный проход учитывает все приказы, историю и автономные действия мира.
5. События последовательно меняют карту; ход можно прервать, сохранить или откатить.
6. Любую механику можно направить в выбранную пользователем модель, прежде всего MiniMax M3 Token Plan.

Цель — поведенческий и UX-паритет. Копировать закрытый код, фирменные ассеты и чужой пользовательский контент не требуется.

## Что установлено об оригинале

### Игровой цикл

- «Решающая пауза»: время не идёт, пока игрок вводит действия и ведёт переговоры.
- В один раунд можно отправить несколько действий; фактическая симуляция и списание происходят на прыжке времени.
- Доступны фиксированные интервалы и auto-jump до следующего крупного события.
- Симулятор управляет всеми неигровыми политиями, создаёт события и изменяет карту.
- Нереалистичные действия могут быть явно отклонены (`voided`), а не незаметно исполнены.
- Во время генерации события применяются по одному; игрок может вмешаться и остановить остаток пакета.
- Есть rewind, сохранения, советник и дипломатические чаты, включая групповые.

### Пресеты

Страница пресета содержит минимум: метаданные и статистику, дату начала, описание, «мир до начала», правила симуляции, стартовую карту, версии, копирование и запуск. Каталог группирует сценарии по жанру и эпохе. Пресет — это не только карта: он задаёт лор, правила и локальные варианты промптов.

Встроенный редактор оригинала показывает отдельные промпты для дипломатии, советника, обычного и автоматического прыжка, действий/подсказок, выбора следующего говорящего, преобразования описания в действие и консолидации истории. В локальных референсах также видны дополнительные роли для катализаторов и game master.

### Карта

Оригинал оперирует регионами, а не только странами. На карте есть политии, внутренние регионы, подписи политий, столицы/города, батальоны и другие точки. Передача территории должна происходить по существующим регионам и учитывать фронт/соседство.

Указанные страницы требуют авторизованного состояния для полного интерактивного просмотра. Поэтому выводы опираются на публичные страницы, доступные описания игрового цикла и сохранённые в репозитории скриншоты/промпты. Для второго конкретного пресета (`Idla5VkKkNnJmTQjo2sa`, версия 24) содержимое публично не раскрылось; его точный лор и карта пока не считаются проверенными.

## Текущее состояние Open-Pax

Сильная база уже есть:

- React/MapLibre-интерфейс, SQLite и локальный Express backend.
- OpenAI-compatible, Anthropic и MiniMax провайдеры с маршрутизацией по механикам.
- Пресет-пакеты, импорт/экспорт, лор, правила и частичные prompt overrides.
- Структурированный JSON симуляции, fuzzy-resolve имён, применение map changes.
- Очередь действий, SSE-прогресс, события по одному, Intervene, rewind и консолидация.
- Советник, подсказки, сохранения, объекты карты и тесты основных контрактов.

Главная проблема — подсистемы существуют, но ещё не образуют тот же единый раунд и тот же устойчивый «живой мир».

## Целевая архитектура раунда

```text
Приказы игрока + выбранная дата
                    |
                    v
         Batch action normalizer (0-1 LLM)
                    |
                    v
       World simulator / planner (1 LLM jump)
                    |
                    v
       Детерминированный validator + resolver
        | schema | даты | имена | топология |
                    |
           точечный repair при ошибке
                    |
                    v
       Транзакционное применение event commands
                    |
                    v
     Timeline + map + state ledger + consolidation
```

Для MiniMax M3 важен режим «один дорогой jump на раунд». Разделять planner и narrator на два обязательных вызова не нужно: модель возвращает и команды, и отображаемый текст в одном структурированном ответе. Повторный вызов допускается только как короткий repair конкретно невалидных команд.

## Приоритетный план

### P0 — правильный и дешёвый раунд

- [x] Обрабатывать все queued actions одним раундом и один раз двигать дату.
- [x] Перевести дефолт MiniMax на модель `MiniMax-M3`.
- [x] Всегда симулировать мир при time-skip, даже если игрок не дал приказов, без создания фиктивного действия игрока.
- [x] Убрать дублирование: автономные NPC-решения входят в общий jump и не порождают несвязанные события после него.
- [x] Держать выбранные и собственные действия локальным черновиком; отправлять окончательный список атомарно только вместе с выбранным периодом.
- [x] Поддержать 1–4 недели/месяца, custom 1–9 недель/месяцев и auto-jump до следующего события.
- [x] Показывать реакции и независимые события последовательно полными карточками; сохранять итог хода в истории ровно один раз.
- [x] Генерировать независимые события общим world-jump из лора и правил пресета, без универсальной 15%-ной случайной таблицы.
- [ ] Добавить usage ledger: provider/model, input/output tokens, latency, retry, cache hit, estimated cost/plan quota на каждый вызов.
- [ ] Добавить лимиты: максимум событий по горизонту, максимальный prompt budget, мягкая консолидация до переполнения.

### P1 — причинность и валидная карта

- Ввести `WorldStateLedger`: активные войны, договоры, союзы, санкции, цели политий, обязательства из событий и приказов, технологические проекты, внутренние кризисы.
- Хранить события структурированно, а не только в `narration`/массиве заголовков.
- Валидировать каждую команду до мутации: существование региона, допустимый владелец, дата в интервале, уникальность id, геометрия, отсутствие противоречащих transfer.
- Построить граф соседства регионов из GeoJSON и запрещать нелогичные сухопутные захваты без морской/воздушной оговорки.
- Применять раунд в SQLite-транзакции; при ошибке откатывать весь неприменённый остаток.

### P2 — агентность мира

- Хранить условия межгосударственных соглашений структурированно и проверять их исполнение в следующих раундах.
- Добавить persistent agenda для ключевых AI-политий и автономную активность вне поля зрения игрока.
- Сохранять цели, угрозы и обязательства политий без отдельного интерфейса дипломатических чатов.
- Дипломатические чаты, group chats и `next_speaker` не реализовывать.

### P3 — пресеты и карта

- Формат preset v2: metadata, semver/version history, regions, polities, features, lore, rules, prompts, validation manifest, thumbnail.
- Импорт базовых карт с административным уровнем 1 для ключевых исторических сценариев; country-level оставить как облегчённый LOD.
- Редактор регионов, политий, флагов, объектов и ownership с validation report до публикации.
- Карта: читаемые подписи по масштабу, collision avoidance, полития как агрегированная подпись, стили фронта/оккупации, компактная карточка выбранного региона.

### P4 — UX-паритет

- Единая нижняя панель режимов: действия и поиск; дата и jump — сверху справа.
- Таймлайн с вариантами 1 неделя / 1, 3, 6, 12 месяцев / custom / next major event.
- Карточки событий синхронно подсвечивают изменившиеся регионы.
- Во время jump: прогресс, текущая фаза, Save, Intervene; после — компактный итог и список отклонённых действий.
- Экран пресета с описанием, правилами, картой, версиями и быстрым выбором политии.

## Система бенчмарков

### Leaderboard моделей и промптов (0–100)

| Метрика | Вес | Проверка |
|---|---:|---|
| Валидный структурированный ответ | 15 | JSON/schema, обязательные поля, отсутствие обрезки |
| Ссылочная целостность карты | 15 | Все регионы/политии разрешаются без fuzzy-угадывания |
| Причинность и учёт приказов | 15 | Каждый приказ исполнен, отклонён или отложен с причиной |
| Player agency | 10 | Симулятор не совершает непрошенные действия за игрока |
| Временная правдоподобность | 10 | Даты внутри интервала, нет анахронизмов и мгновенных мегапроектов |
| Географическая правдоподобность | 10 | Фронт/соседство/морской доступ и постепенные transfers |
| Последовательность мира | 10 | Нет противоречий с войнами, договорами, прошлым владением и обязательствами политий |
| Качество автономного мира | 5 | Значимые события происходят не только рядом с игроком |
| Нарратив и язык | 5 | Читаемость, конкретика, язык пользователя, отсутствие мета-текста |
| Эффективность | 5 | p50/p95 latency, вызовы/раунд, токены/раунд, ошибки/retries |

Итоговый рейтинг публикуется вместе с hard-fail rate. Модель с красивым текстом, но 20% невалидных map changes не может занимать первое место.

### Набор сценариев

Минимум 30 фиксированных кейсов с одинаковым seed/state:

- 8 мирных: экономика, исследования, реформы, строительство, санкции.
- 8 межгосударственных: союз, ультиматум, многосторонняя конференция, нарушение договора.
- 8 военных: мобилизация, ограниченная война, морская операция, гражданская война, капитуляция.
- 3 отрицательных: захват мира за неделю, анахронизм, несуществующий регион.
- 3 долговременных trajectory: 10–25 раундов с проверкой памяти и дрейфа состояния.

Каждый кейс запускается минимум три раза на модель/промпт. В отчёте показываются средний балл, разброс, hard-fail rate, latency и токены. Для сравнения промптов используется одинаковая модель, температура и состояние.

### Тестирование карт

- GeoJSON validity и допустимые координаты.
- Уникальные region ids/names внутри пресета.
- Ownership ссылается на существующую политию.
- Нет непреднамеренных gaps/overlaps для административных карт.
- Граф соседства стабилен; острова и проливы размечены отдельно.
- Автоматический render на 3 масштабах и visual regression.
- Label collision/читабельность и FPS/pan latency на целевом компьютере.
- Round-trip: transfer/create/update/delete → save → reload → rewind без потери геометрии и объектов.

## Критерий «достаточно похоже» для первой публичной версии

- 95%+ ответов проходят schema и referential validation без ручного ремонта.
- Один раунд с 1–5 приказами использует один основной jump-вызов.
- 20-раундовая golden trajectory не теряет войны, договоры и территориальные изменения.
- 90%+ военных transfers проходят topology validator.
- Полный save/reload/rewind восстанавливает идентичный checksum состояния.
- p95 раунда MiniMax M3 укладывается в выбранный UX-бюджет; UI всегда показывает фазу и не выглядит зависшим.
- Карта остаётся читаемой на world/region zoom и не имеет критических label collisions.

## Сделано в первом проходе

1. Очередь действий стала атомарным раундом: несколько приказов конвертируются пакетом, симулируются одним jump и получают один номер хода/один интервал времени.
2. Добавлен регрессионный тест, проверяющий один converter, один jump, один turn result и одно продвижение даты для двух приказов.
3. Дефолтная модель MiniMax обновлена до `MiniMax-M3`; в example-конфиг добавлен Token Plan.
4. Любой time-skip без приказов запускает полноценный автономный world jump. Converter не вызывается, фиктивное действие и строка в истории приказов не создаются; результат мира сохраняется как обычный раунд и поддерживает rewind.
5. Удалён второй per-NPC LLM-проход после world jump: все неигровые политии теперь моделируются в одном общем вызове, без N дополнительных запросов и конфликтующих изменений состояния.
